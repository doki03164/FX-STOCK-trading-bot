# FX / US 交易操作手冊 的程式化版本

把 `交易操作手冊.html` 的 **GATE 1–7** 與 **18 項進場前提條件（A1–E4）** 寫成可執行的程式，
在兩個市場、三種執行週期上重跑，並用大規模參數掃描檢驗手冊裡每一個門檻值到底有沒有用。

| 市場 | 標的 | 資料量 | 回測次數 |
|---|---|---|---|
| **外匯** | 46 組貨幣對（G10 全組合 + 北歐/新興） | 127 萬根 K 棒，日線回溯 1996 | 118,800 |
| **美股** | 499 檔 S&P 500（API 掃描全市場） | 512 萬根 K 棒，日線回溯 2011 | 79,200 |

策略引擎完全共用——結構、GATE、風險計算從不問自己在看什麼。只有三件事真的不同，
全部集中在 `markets.py`：標的清單、交易成本（固定點差 vs 名目本金的基點）、交易時段。

> **這個程式不會下單。** 它產生訂單參數（進場區、SL、TP、手數），GATE 7 的按鈕由你自己按。
> 本專案僅供研究與紀律練習，不構成投資建議。

---

## 一鍵啟動

```bash
python start.py
```

Windows 也可以雙擊 `start.bat`。

它會自動檢查 Python、安裝相依套件、補齊缺少的資料（首次約 20 分鐘：下載報價 + 跑回測，
之後每次啟動只要幾秒），然後開啟瀏覽器顯示儀表板，並在背景每根 1H K 棒收線後自動重掃。

其他平台：

```bash
pip install -r requirements.txt && python app.py
```

儀表板頂端會有一條控制列：資料時間、可下單筆數、**重新掃描**按鈕、自動更新開關。
按下重新掃描約 40 秒（抓報價 → 掃描 → 重建），完成後頁面自動重載。

### 手動執行各步驟

若想分開跑或排進排程：

```bash
python fetch.py     # 下載 1H（730 天上限）與完整日線，衍生 4H / 週線 / 月線
```
```bash
python sweep.py     # 大規模參數掃描 -> sweep.csv + candidates.parquet
```
```bash
python live.py      # 抓報價 → 掃描 → 重建儀表板（約 1 分鐘，不重跑回測）
```

## 24 小時監控

1H 策略的每一根 K 棒都是決策點，所以有一個常駐監控：**每根 1H 收線後（整點過 90 秒）**
自動增量抓取、重掃三個階梯、重建儀表板，並把「狀態變化」寫成事件流。

```bash
python watch.py
```

Windows 可以直接雙擊 `watch.bat`（已處理好中文編碼）。

它印出的是**變化**，不是整本帳：昨天在等、今天還在等的計畫不是新聞；剛變成可下單的才是。
這些轉換會寫進 `events.jsonl`，並顯示在儀表板「即時訊號」分頁最上方：

| 事件 | 意思 |
|---|---|
| `✓ 可下單` | 條件全過且價格已到區——**會響一聲提示音** |
| `· 新計畫` | 出現新的結構計畫，等價格到區 |
| `× 區域被貫穿` | 價格帶動能直接切穿，計畫作廢 |
| `× 條件不再成立` | 某一關由通過轉為不通過 |

其他選項：

```bash
python watch.py --every 15
```
```bash
python watch.py --once
```

- 自動跳過外匯休市時間（週五 21:00 UTC → 週日 21:00 UTC）
- 單一輪失敗不會中斷監控（等 60 秒重試）
- 增量抓取一輪約 33 秒，只抓最近 7 天的 1H 與 1 個月的日線再合併
- `Ctrl-C` 結束

> 這個監控要跑在**你自己的終端機**才會 24 小時持續；關掉視窗就停了。
> 想開機自動啟動，用 Windows 工作排程器指向 `watch.bat` 即可。

`fetch.py` 會跳過已下載的貨幣對，要全部重抓加 `--force`。
只想快速測一下：`python sweep.py --quick`。只掃日線：`python live.py 1d`。

## 儀表板有兩個分頁

**即時訊號**（預設）— **每 10 秒自動更新**，把當下的標的分成四類：
可下單／等待價格到區／條件未通過／已失效。每張卡片直接給：

- **何時進場** — 掛單價、掛哪一種單、成交後要不要看收線確認
- **何時出場** — 停利價、停損價、結構失效價（收線越過就手動平倉）、計畫到期日
- 手數、風險金額、RR、共振因素逐項列出、以及沒過的是哪幾關

### 分段式更新

整本計畫（外匯 47 筆 + 美股 283 筆）沒辦法每 10 秒全部重抓，所以按優先級分段輪替：

| 層級 | 內容 | 更新頻率 |
|---|---|---|
| **第一層** | 可下單 + 等待進場的計畫 | **每一輪**（10 秒）——這裡的報價過舊才會害人 |
| **第二層** | 其餘計畫 | 每輪輪替約 50 檔，全書約 60 秒轉一圈 |

計畫本身（結構、共振、SL/TP、手數）只在 K 棒收線後重算，因為那些在 K 棒中間本來就不會變。
每個報價都帶 `age`，超過 3 分鐘的報價**不允許**用來判定「可下單」——會改顯示
`⚠ 報價過舊，先重新掃描`，而不是假裝新鮮。

### 狀態判定（一個曾經很嚴重的 bug）

原本 `in_zone` 只檢查 `price <= zone_hi`，**沒有下界**；而失效判定只看 `invalidate`
（區間外 0.5×ATR），但停損只在區間外 0.2×ATR。做多時三者的順序是：

```
invalidate  <  SL  <  zone_lo  <  zone_hi = 進場價
```

所以價格跌穿整個進場區、甚至已經觸及停損，畫面還是顯示「可下單」。實際發生過：
CrowdStrike 做多、區間 180.27–192.54、現價 179.42 —— 已經在停損附近，卻仍列在可下單。
修正後美股 283 筆計畫裡有 **83 筆**被正確重新歸類（74 筆已觸及停損、9 筆已跌穿進場區）。

現在的狀態機（`quotes.restate`，掃描器與即時刷新共用同一份，不再各寫一套）：

| 狀態 | 意思 |
|---|---|
| `✓ 現在可下單` | 價格在區間內，且 18 項前提全過 |
| `· 等待價格到區` | 條件都過，價格還沒回到區間 |
| `× 已跌穿進場區` | 掛單已成交且不利，不是新機會 |
| `× 已觸及停損` | 這筆計畫結束 |
| `× 帶動能貫穿，作廢` | 超過 invalidate |
| `⚠ 報價過舊` | 該檔報價超過 3 分鐘，不足以判斷進場 |

> **這個分頁不會下單。** 零售外匯沒有可用的下單 API，所以程式只算訂單參數，
> 送單與核對由你在券商平台完成——這也正是手冊 GATE 7 的設計。

**回測研究** — 三週期績效比較、參數掃描熱圖、樣本外檢驗、GATE 漏斗、月報酬熱圖等。

## 週期階梯

手冊把週期分工成「日線＝能不能做 / 4H＝有沒有空間 / 1H＝怎麼做」。這是一個**階梯**，
整個往上搬就得到另外兩組執行方式，程式把三組都跑：

| 執行 | 看空間 | 看方向 | 資料量 |
|---|---|---|---|
| 1 小時 | 4 小時 | 日線 | 787k 根，2023-10 起 |
| 4 小時 | 日線 | 週線 | 204k 根，2023-10 起 |
| 日線 | 週線 | 月線 | 277k 根，**1996 起** |

1H 受限於 Yahoo 的 730 天上限；日線沒有這個限制，所以日線那一組有近 30 年、
跨越多個利率循環的資料——這也是為什麼日線的樣本外檢驗遠比 1H 可信。

## 四個週期的績效

同一套挑法：**先要求樣本內外都為正**，再依年均 R 排序。四個都是正的。

| 市場 / 週期 | 回測長度 | 交易 | 每筆 | CAGR | 最大回撤 | 樣本內 / 樣本外 |
|---|---|---|---|---|---|---|
| 美股 4H | 2.9 年 | 401 | +0.102R | **+35.0%** | −9.2% | +0.247 / +0.176 |
| 美股日線 | **14.9 年** | 656 | +0.159R | +2.8% | −24.4% | +0.063 / +0.115 |
| 外匯 4H | 2.9 年 | 118 | +0.124R | +7.3% | −8.1% | +0.210 / +0.112 |
| 外匯日線 | 23.9 年 | 212 | +0.096R | +0.4% | −10.3% | +0.051 / +0.045 |

**美股日線是整個專案裡唯一讓手冊 E1（RR ≥ 1:2）照原文成立的地方。** 這個門檻在 1H 外匯上
永遠達不到——TP 釘在前一個結構高低點，價格回撤到共振區後只剩 1～1.5R。日線股票的擺盪
夠大，同樣的幾何就付得起 1:2。手冊 §07 的數字是對的，只是寫在錯的市場上。
該組在 39,600 次美股日線回測中 t 統計量最高（**4.28**），1,086 組通過雙半期檢驗。

**兩個要留意的地方。** 美股日線 CAGR 小不是訊號差：每筆 +0.159R、一年 45 筆，訊號本身
產出約 22.7 R/年，但同時持倉上限、相關性淨額加上 24.4% 的回撤把大部分吃掉了。
另外 **4H 的 10 年回測做不到**——Yahoo 小時線硬性上限 730 天，4H 最多 2.9 年，
所以美股 4H 的 35% 不能和日線的 14.9 年並排解讀。

## 結論（先講重點）

以下針對外匯 1H 階梯，是這份手冊最初設定的市場：

| 發現 | 數字 |
|---|---|
| 手冊原始 18 項門檻產生的交易 | **0 筆** |
| 同一設定只調 E1：RR≥0.5 / 1.0 / 1.5 / 2.0 | 1072 / 636 / 51 / **6** 筆 |
| 樣本內↔樣本外 相關係數：1H / 4H / 日線 | +0.15 / +0.38 / **+0.69** |
| 以樣本內挑出的前 25 名，樣本外平均（日線） | **−0.05R**（樣本內 +0.16R） |
| 118,800 次回測中，樣本內外都 > +0.05R 的 | **168 組**（1H 109、日線 53、4H 6） |
| 參考設定（1H 階梯，掃描高原中心） | 454 筆 · +0.088R · PF 1.14 · 最大回撤 14.0% |

**1 · E2 做得到，E1 做不到。**
把 HPCZ 的半寬設成 ±1×ATR、停損放在整個區帶之外，停損距離自然就是約 2.2×ATR ——
**E2（SL ≥ 2×ATR）幾乎不刷掉任何交易**。真正的懸崖是 E1：TP 被釘死在「前一個結構高／低點」，
價格回撤到共振區時剩下的距離就只有 1～1.5R，所以 RR 門檻從 1.0 拉到 1.5 就從 636 筆掉到 51 筆。
**手冊 §12 寫了「是否適合你，必須由你自己的回測數據決定」，這就是那個數據。**

**2 · 換到 4H 或日線不能解決幾何問題，但日線的結論可信得多。**
成本大幅下降（1H 0.076R → 日線 0.014R 每筆），但推動浪的 ATR 倍數幾乎不變
（7.1 / 7.5 / 7.3）——市場結構是碎形的，E1/E2 的衝突跨週期存在。
不過日線有近 30 年、跨越多個利率循環的資料，樣本內外相關係數 **+0.69**（1H 只有 +0.15），
所以日線上掃出來的東西比較不是雜訊——即使結論是「優勢很小」。

**3 · 但手冊的部分規則確實有效。** 在多數設定下都能提升期望值的是：

- **GATE 2 趨勢成熟度**（推動浪 ≤ 2，也就是「早期／中期」）— 效果最明顯
- **GATE 3 B1 日線階段明確**
- **GATE 4 共振數 ≥ 4**
- **GATE 6 確認 K 棒**（影線／吞噬／pin bar）

拖累績效的是 E1／E2 的**絕對數值**，不是概念本身。

## 參考設定不是「最佳解」

儀表板報告的參考設定，是掃描中**唯一一塊鄰居格在樣本內外都為正的高原**，不是單一最高分。
一根周圍全是虧損的尖峰是過度擬合；一整片高原才是（弱）證據。

```
執行階梯     1 小時執行 / 4 小時看空間 / 日線看方向
進場方式     limit（掛單，手冊 GATE 7 的第二種）
停損位置     zone（整個 HPCZ 之外，而非影線低點之外）
zigzag 門檻  3.0 × ATR       共振帶半寬  ±1.0 × ATR
共振數 ≥ 4   RR ≥ 1.0        SL ≥ 2.0 × ATR（由區帶寬度自動達成）
推動浪 ≤ 2   多週期：日線階段明確（不要求 4H 對齊）
```

即使如此，**+0.088R 的期望值遠低於可以實盤的標準**：把點差成本再抬高 30%，或把資料換成
另一段期間，這個優勢就會消失（樣本外只剩 +0.043R）。手冊第 12 節建議「累積至少 100 筆手動
回測與一個月模擬盤」之後再談真錢——這個結論在這裡依然成立。

### 三個週期各自調參後的結果

原本三個週期都套用同一組（為 1H 調的）參數，4H 因此看起來很爛（−0.178R）。
各自從掃描結果挑自己的高原之後（一樣先要求樣本內外都為正，再依**年均 R** 排序，
因為高週期的問題是機會太少而不是每筆品質差）：

| 週期 | 參數差異 | 交易 | 每年 | 期望值 | CAGR | 最大回撤 |
|---|---|---|---|---|---|---|
| 1 小時 | 共振≥4 · RR≥1 · 推動浪≤2 · 日線 | 454 | 164 | +0.052R | 14.2% | −14.0% |
| 4 小時 | 共振≥4 · RR≥0.5 · **不限推動浪** · 日線+4H | 118 | 43 | **+0.124R** | 7.3% | −8.1% |
| 日線 | limit_confirm · 共振≥3 · RR≥1 · **不限推動浪** | 212 | 9 | +0.096R | 0.4%※ | −10.3% |

※ 日線的 CAGR 被 24 年的期間攤平；在三個週期都存在的共同期間（2023-10 起），
日線是每筆 +0.427R、CAGR 3.2%、最大回撤只有 2.9%。

兩個高週期都**放寬了 GATE 2 的成熟度上限**（推動浪 ≤2 → 不限）——在 4H 與日線上
這一關只是在減少交易，沒有增加優勢。三組都保留 ±1×ATR 的區帶，所以停損距離自動
是 2.2×ATR，**E2 仍然成立**。

### 三週期合併成一個帳戶

高週期單獨跑機會太少（4H 43 筆/年、日線 9 筆/年），但它們**開單的時間點和 1H 不同**，
所以疊在同一個帳戶上可以在不加大單筆風險的情況下提高機會數。共同期間結果：

| | 年均 R | CAGR | 最大回撤 |
|---|---|---|---|
| 只跑 1 小時 | 11.5R | 13.8% | −14.0% |
| **三週期組合** | **18.2R** | 10.2% | −20.2% |

年均 R 明顯提高，但 CAGR 反而略降、回撤變大——因為相關性與同時持倉上限（4 筆）
是**跨週期一起算**的，有 301 筆被帳戶層規則擋掉，擋掉的多半是原本 1H 能吃到的單。
想真正吃到組合的好處，得先把 `ACCOUNT["max_open"]` 調高（目前 4 筆 × 1% 風險，
離手冊的「保證金 <80%」還很遠），那是你自己的風險決定，程式不替你調。

### 頻率預算對不上高週期

手冊的頻率上限是**每週 3–4 筆**（約每年 180 筆）。同一組門檻下實際跑出來的頻率：

| 執行週期 | 每年交易筆數 |
|---|---|
| 1 小時 | 228 |
| 4 小時 | 69 |
| 日線 | 5.4 |

只有 1H 階梯接近手冊的頻率預算。若要在日線上執行，手冊的「每日 ≤2 筆、每週 3–4 筆」
這些節流規則基本上永遠不會觸發，帳戶層的保護就只剩下虧損熔斷。

## 檔案結構

| 檔案 | 作用 |
|---|---|
| `markets.py` | 兩個市場的定義：標的清單、成本模型、交易時段 |
| `config.py` | 市場切換、週期階梯、成本函式、手冊預設值、帳戶規則 |
| `fetch.py` | 外匯：下載 1H 與完整日線，重採樣出 4H／週線／月線 |
| `fetch_us.py` | 美股：S&P 500 成分股 + 15 年日線 + 730 天小時線（批次下載） |
| `structure.py` | 擺動點、HH/HL/LH/LL 標籤、趨勢方向與成熟度、水平位／趨勢線／斐波那契 |
| `loader.py` | 讀檔 + 把兩個高階週期對齊到執行週期（防止跨週期偷看未來） |
| `gates.py` | **GATE 1–7 本體**；產生候選交易並記錄每一項前提條件的實際數值 |
| `backtest.py` | 帳戶層模擬：1% 風險、相關性淨額、每日 2 筆上限、2%／5% 熔斷 |
| `sweep.py` | 結構參數 × 過濾參數的網格掃描，每格都切樣本內／外 |
| `report.py` | 各週期參數（`LADDERS`）、組出 `dashboard_data.json` → `dashboard.html` |
| `bot.py` | 即時掃描三個階梯，輸出訂單參數與進出場時機 → `plan.json` |
| `live.py` | 一行完成「抓報價 → 掃描 → 重建儀表板」 |
| `watch.py` | 24 小時常駐：每根 1H 收線後重掃，變化寫入 `events.jsonl` |
| `quotes.py` | 10 秒即時重定價：只抓 live 計畫的報價，重判進場狀態 |
| `start.py` / `app.py` | 一鍵啟動：自動補資料、開本機伺服器、開瀏覽器、背景監控 |

每個市場的產物都帶後綴（`sweep_fx.csv` / `sweep_us.csv`、`dashboard_fx.html` /
`dashboard_us.html`…），用 `--market fx|us` 切換。資料與回測產物約 1 GB，不進版控——
都能重新產生，`python start.py` 會自動補齊。

## 沒有偷看未來（這份程式最在意的事）

一個回測要騙人非常容易，所以以下幾點是硬性設計：

1. **擺動點有確認延遲。** 左右各 5 根的分形，要到 5 根之後才「存在」。所有結構狀態都是
   依照*確認 K 棒*重播出來的，第 i 根讀到的結構，是當下真的畫得出來的結構。
2. **高週期只看已收線的。** 1H 第 t 根只能看到在 t 之前就已經收線的 4H／日線 K 棒。
   用開盤時間 join 會直接把那根 4H 的後半段餵給策略。
3. **掛單不能挑收線形狀。** 掛單是盤中成交的，你無法根據「那根 K 棒最後怎麼收」決定要不要
   成交——所以 `limit` 模式**不允許**用確認 K 棒當過濾條件。
   `limit_confirm` 模式的處理方式是：成交後若當根沒出現拒絕訊號，就在收盤價認賠出場。
4. **E2 用決策當下的 ATR。** 掛單用計畫當下那根的 ATR，市價單才用確認 K 棒的 ATR。
5. **同一根同時碰到 SL 和 TP 一律算虧損**；停損遇跳空以開盤價成交，停利只給限價價位。
6. **成本從嚴。** 點差 + 佣金 + 滑價，平均約佔每筆 0.15–0.18R。

## 已知限制

- **資料來源。** Yahoo Finance 的外匯報價是**指示性中間價**，最高／最低價的品質不如真實
  tick 資料。影線判定（GATE 6）與停損觸發都會受影響。要認真做，需要換成券商的真實報價。
- **回測長度。** Yahoo 的小時線上限約 730 天（實際取到 2.8 年），所以 1H 與 4H 兩個階梯
  的樣本外期間都很短；以每格 50–300 筆交易來說，期望值的雜訊約 ±0.15R，
  **和觀察到的優勢是同一個數量級**。日線階梯沒有這個問題。
- **非 G10 的點差是估計值。** USD/TRY、USD/ZAR 等的實際成本會隨波動大幅變動，
  這裡用的是倫敦盤時段的典型報價；若你的券商更貴，這些貨幣對的貢獻會再往下修。
- **新聞過濾未實作。** 手冊 E4 要求「未來 4 小時內無高影響力新聞」，本專案沒有經濟日曆資料，
  這一項在回測中恆為通過。實盤時請自行檢查。
- **未計入展期利息（swap）**，對持倉數日的部位會有影響。
- **未模擬掛單排隊與部分成交。**
